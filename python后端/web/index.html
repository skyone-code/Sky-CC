实现说明 数据来源与原理

原来散在各卡片里的原理说明集中收在这里，每条头部标注它属于哪个模块；功能卡片只保留操作指引。
监控 · CPU

占用率由 host_processor_info 采两次 CPU 时间片计数求差得出， 是距上一次刷新这段时间的平均值（刷新间隔 2 秒），不是瞬时值。 温度走 VirtualSMC，功耗 / 电流走 SMC 的 sp96 定点键。

监控 · GPU

独显这一格是 EC 0x044F 的实测值：12 进程满载 35 秒的实验里 CPU 从 64℃ 冲到 89℃，0x044F 只从 60℃ 动到 62℃， 说明它确实不在 CPU 那一路，是独显散热区的传感器。 核显那一格不在这里——它是 CPU 封装温度的参考值（UHD 630 与 CPU 同封装、 本机无独立热敏），已经挪到上面的 CPU 模块里，跟它真正的来源放在一起。 占用率与功耗读不到，所以不显示。 macOS 没有开放 GPU 利用率的用户态接口；独显在 macOS 下只有一个 PCIe 设备条目 （无官方驱动、始终空载），核显也不上报利用率。

监控 · 风扇

两颗风扇收到的其实是同一条命令。 12 进程满载 35 秒实测：PWM1 与 PWM2 每一步数值都相同（80 → 96/96 → 117/117 → … → 177/177）， 也就是 EC 给两颗风扇的是同一个占空比。所以转速差（约 12%） 纯粹来自风扇本身的型号/个体差异——独显在 macOS 下无驱动、始终空载， EC 也不会因为「GPU 凉」就单独给它降速。 归属是用户实物确认的：他亲手换过 CPU 风扇，转速较高的 0x046C 才是 CPU 风扇，0x0464 是 GPU 风扇 （2026-10-16 修正，之前标反了）。因为两路占空比恒等，这个对应关系 对实际控制没有任何影响，只影响显示是否跟物理机器对得上。 转速直读 EC（大端），不走 SMC——本机 VirtualSMC FNum=0， 根本没建风扇模型。需要 TongfangFan.kext 已加载，否则显示「不可用」。

监控 · 电池

数据源 ioreg -r -c AppleSmartBattery + pmset -g batt。

监控 · 磁盘

硬盘温度：本机读不到，所以不显示。 已经把可能的来源都查了一遍：SMC 只枚举出 TC* 那一串 CPU 温度键， 没有 TH* / Tm* 这类硬盘键；ioreg 里 IONVMeController 与 IOBlockStorageDevice 都不上报温度（全系统唯一的 Temperature 键是电池的 29.3℃）； EC 页 0x04 整页扫下来也没有像硬盘热敏的寄存器。 常规做法要靠 smartctl（smartmontools），但本机既没装它也没有 brew， 而且 macOS 上读 NVMe SMART 通常要管理员权限，控制台是以普通用户权限跑的。 要是你装了 smartmontools 且愿意给它授权，说一声我就把它接进来。

监控 · 进程

进程列表走 ps 快照（后端每轮刷新采一次）， Top 8 按 CPU 占用排序；沙箱环境里 ps 不可用时会显示为空。

键盘灯 · 海岸灯

与 OEM 控制台同样只有三个操作：多彩（轮换动画，机器出厂就是这个状态）、 应用颜色（定在你选的色上）、关闭。 走 EC 0x0748 控制字节 + 0x0749-0x074B RGB 三通道， 与 OEM 的 DefaultRGBLightbar 同一组寄存器。 三个取值均已肉眼验证：0x80 多彩 / 0x00 固定色 / 0x84 关灯 （bit7 = 轮换位，bit2 = 关灯位）。按钮高亮来自 EC 回读的真实状态。

键盘灯 · 预设灯效

自定义颜色走「命名色」命令 0x14 把 RGB 写进槽位 1， 再让灯效包的 colour 字节指向该槽位 —— 灯效包里只有一个字节的 colour，装不下 RGB。 这条是按协议推导出来的：下发返回 kr 都是 0，但颜色到底变没变需要你肉眼确认 （设备没有可靠的回读通道，read_feature 拿到的都是陈旧缓冲）。 想要「一定生效」的自定义颜色，用下面的分区配色——那条是实测过的。

键盘灯 · 分区配色

这颗键盘物理上是 6 行 × 21 列。给每一行单独指定颜色，走 0x16 选行 + 64 字节分平面行缓冲下发；行数不足时按最后一行重复填充。 应用后会一并写进「已记住的灯效」，开机自启恢复的也是它。

键盘灯 · 白色校准

这颗灯条的蓝光 LED 效率偏高，直接下发纯白会发蓝（OEM 原厂也有 ColorCalibration 流程）。 下面一排是纯白指令下你肉眼实际看到的样子，点选最接近的那个，系统自动反算三通道增益。

控制 · 散热模式

经 TongfangFan.kext → WMI (ABBC0F6F) → EC 邮箱下发，与 Windows 版 Control Center 同一条通路。先开 CTRL_1 手动门，再写 FAN_CTRL (0x0751)： 自动=交回 EC 调度，基准=拉满 78% 占空比（约 5500 RPM）， 档位 0-7=手动阶梯（24%~53%）。重启后由控制台自动恢复。

控制 · 屏幕亮度

面板处于 PWM 模式时由 macOS 原生链路驱动：写「系统亮度」即可到达屏幕（自带原生渐变）。auxbright 守护负责保持 PWM 模式（睡眠唤醒后自动恢复）；旧的双路写入/平滑层方案已废弃。

其他 · 电流 / 功耗 / 电压

SMC 的功耗键漂移较大（同条件重复基线能差 20%+），看趋势可以，别当精确功率计用。
